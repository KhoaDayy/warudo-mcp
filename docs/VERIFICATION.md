# Capability and verification record

This record separates automated/source verification from the final compiled-plugin acceptance pass. Protocol v2 was exercised against running Warudo 0.15.0 during the refactor: scene loading completed without the earlier crash, native port 19053 and bridge port 5678 stayed connected, and handshake, scene inventory and blueprint listing succeeded. The compiled `[PluginType]` packaging and lifecycle still require the live acceptance checks below after installation.

## Evidence used

- Local source baseline: Git `4de7da2`.
- Native API contracts inspected from the installed `Warudo.Core.dll` using Mono.Cecil metadata and method IL, without running the application.
- Generic bridge compiled against the installed Warudo managed assemblies using Unity's bundled Mono/Roslyn compiler.
- Protocol behavior exercised with local fake WebSocket servers and real stdio subprocesses.
- npm tarball installed into an isolated temporary directory and its built entrypoint exercised over stdio, with Warudo endpoints disabled.

## Backend decisions

| Capability | Backend in 0.3 | Verification |
|---|---|---|
| Selected asset/graph, plugins, type lists | native | source contract + fake protocol tests |
| Read/write data inputs | native | DLL confirms setter takes serialized JSON string; vector/color fixtures and dispatch tests |
| Entity metadata | bridge | actual input/output/trigger/flow port APIs compile against installed DLLs |
| Full scene asset/graph inventory | bridge | compiled source; native fallback explicitly partial |
| Graph create/remove/rename/enabled | native typed tool | local DLL action/payload audit + dispatch tests |
| Node create/remove | native typed tool | local DLL action/payload audit + dispatch tests |
| Data/flow connection add/remove | native typed tool | local DLL action/payload audit + dispatch tests |
| Flow input invocation | native typed tool | local DLL action/payload audit + dispatch tests |
| Graph import/export | native | dictionary-based serialized graph schema + local shape validation |
| Hierarchy, active, material | bridge | compiled source; Unity rendering behavior needs live smoke |
| User-authored flow invocation | native typed tool | `warudo_invoke_flow`; the MCP plugin registers no Blueprint node |
| Other native actions | compatibility tool | not represented as fully verified typed contracts |
| REST 19052 | not added | no live evidence justifying a third client |

Native `BroadcastOpenedScene` exists, but full-scene synchronization across subsequent changes has not been demonstrated. Therefore the bridge is retained for complete inventory. It is not proven that native-only operation is impossible.

## Verified commands

From `mcp-server/`:

- `npm run check`: strict typecheck, Node test suite, production build and package allowlist.
- `npm run test:install`: npm tarball install in a temporary directory, real stdio initialize/tools-list/status/EOF shutdown; no global install or publishing.

From repo root:

- `powershell -NoProfile -File scripts/check-bridge.ps1`: compile the four plugin C# files; managed response-budget checks including UTF-8 and escaped JSON.

Tests cover same-action request serialization, out-of-order bridge replies, notification interleaving, stale export replies, timeout/socket retirement, shutdown during token discovery, malformed response envelopes, strict tool inputs, opaque plugin messages, native value serialization, graph payload dispatch and blueprint validation. CI defines Windows/Linux jobs; only local execution is claimed here.

## Limits and semantics

- Requests: 1 MiB transport cap; graph import input 900 KiB to leave envelope room.
- Bridge responses: 4 MiB serialized UTF-8 cap.
- Bridge listings: 10,000 assets, 256 graphs, 10,000 blueprint nodes; inspect metadata maximum 4,096 ports.
- Hierarchy: 10,000 returned entries and 200,000 traversed transforms, with depth cap.
- Native calls are serialized. An unanswered sent operation is `UNKNOWN`; queued unsent work is `NOT_EXECUTED`. No automatic mutation retries.
- Bridge protocol v2 returns explicit `isResponse: true`. This is generated by our bridge because the base native `WebSocketService.Respond` only emits `action/error/data`.
- Manual Warudo dialogs are not auto-answered. The MCP connection is retired when one interrupts a request; UI completion and request outcome require state inspection.
